## Problem

Customer workflows span many projects, modalities, datasets, and compute environments. Errors can occur in processing jobs, database states, worker execution, algorithm configuration, cloud resources, and data movement. Labs need a way to know what failed, where, and why.

## System Concept

A monitoring layer that tracks:

- pipeline status
- jobs pending/running/failed
- error messages and stack traces
- table-level progress
- modality-level workflow status
- customer/project context
- worker health
- cloud compute status
- links to logs or database records
